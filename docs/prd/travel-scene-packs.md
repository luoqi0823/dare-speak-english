# 旅行场景急救包 PRD

## 1. 产品定位

旅行场景急救包面向“马上就要用英语完成一件事”的用户。它不是 30 节系统课程的前置或支线课程，不要求登录、不锁定顺序，也不读写课程进度。

内容遵循“整句优先、单词服务于整句”的原则：先让用户听见并说出一句可以直接使用的话，再通过替换词和三轮微对话完成一个真实任务。

## 2. 信息架构

首页旅行英语区域分为三层：

1. 高频主场景：机场、酒店、餐厅，以大卡片呈现。
2. 路上常用：交通问路、景点门票、付款求助，以紧凑入口呈现。
3. 目的地实战：第一期为冰岛自由行，覆盖机场接送、租车自驾、天气道路、活动集合与突发求助。

每个场景包包含：

- 3 个真实任务。
- 每个任务 4 句高频表达、6 个替换词和 1 段微对话。
- 首屏从全部内容中挑选 4 句“现在就能用”的表达。
- 每句英文提供独立发音按钮，不把整张内容卡做成播放按钮。

## 3. 第一批场景

| 场景 | 用户要完成的任务 |
|---|---|
| 机场 | 办理值机、安检登机、入境抵达 |
| 酒店 | 办理入住、解决房间问题、退房离店 |
| 餐厅 | 入座点餐、说明口味忌口、打包买单 |
| 交通问路 | 打车、乘坐公交、步行问路 |
| 景点门票 | 现场购票、核验预约、确认开放规则 |
| 付款求助 | 购物付款、处理支付问题、寻求紧急帮助 |
| 冰岛自由行 | 机场接送、租车自驾、天气道路与户外活动 |

冰岛内容使用通用旅行英语承载当地高频任务，不教授冰岛语，也不把会变化的价格、班次或开放状态写死在课程内容中。涉及路况、天气、车型限制时只教授询问方式，实际信息仍应由用户向现场人员或官方渠道确认。

## 4. 页面与交互

- 首页卡片点击进入 `/travel/[slug]`，不再跳转 `/learn`。
- 场景详情页公开访问，顶部可以返回首页旅行场景区域。
- 发音继续使用浏览器语音合成；不申请麦克风权限、不上传录音。
- 详情页按“急用 4 句 → 3 个任务 → 常用词 → 微对话”的顺序阅读。
- 任务内容一次展开显示，避免把救急内容藏在多层步骤和弹窗中。
- 桌面和手机均保证发音按钮可单独聚焦，英文、中文和操作不重叠。

## 5. 数据与维护

- 场景内容由版本化 TypeScript 静态数据维护，页面从同一数据源生成，避免首页文案和详情内容分叉。
- 场景 `slug` 是稳定路由标识，不使用中文或展示标题作为主键。
- 通用场景和目的地包使用同一结构；未来增加日本、泰国等目的地时不新增另一套页面实现。
- 第一版不接入数据库，不新增完成进度、收藏或录音评分。

## 6. 验收标准

| AC | 验收标准 | 验证方式 |
|---|---|---|
| AC-01 | 首页展示 3 个主场景、3 个路上常用入口和 1 个冰岛专题入口 | 桌面与手机页面巡检 |
| AC-02 | 所有入口进入对应公开场景页，未登录用户不会被重定向登录 | 路由与浏览器回归 |
| AC-03 | 每个场景包含 3 个任务，每个任务包含 4 句、6 词和 1 段微对话 | 数据结构校验、代码审查 |
| AC-04 | 任一句英文可独立播放，播放不会触发页面跳转 | 浏览器交互回归 |
| AC-05 | 场景页面不调用课程进度接口，也不修改本地课程状态 | 网络与实现审查 |
| AC-06 | 360px 手机宽度无横向溢出，关键按钮不被底部导航遮挡 | 响应式浏览器验证 |
| AC-07 | 类型检查、ESLint 和生产构建通过 | 自动检查 |
