# 品牌视觉统一与登录页优化 PRD

## 1. 背景与目标

当前公开体验页、登录页、云端课程页、错题本和浏览器图标分别维护了不同的“敢”字标记，尺寸、轮廓和文字组合不一致。登录页左侧还使用大面积装饰圆承载小图标，品牌层级偏弱，容易被误认为临时占位。

本次目标是建立单一品牌视觉组件，在不改变登录、注册和学习流程的前提下，统一所有页面的 Logo，并优化登录页首屏的信息层级、留白与响应式表现。

## 2. 设计原则

- 延续现有纸张、印章和手作学习卡片的视觉语言。
- Logo 使用统一的珊瑚色“敢”字对话印章，搭配“敢说英语”字标；需要时可显示一句简短副标题。
- 页面只组合共享品牌组件，不再各自绘制圆形图标或维护字号、旋转角度。
- 登录页突出“跨设备继续学习”的价值，不新增与认证无关的交互。
- 品牌副标题与课程时长统一使用“每天 6 分钟”，不得与课程数据和首页文案分叉。
- 动效服从 `prefers-reduced-motion`，图形和文字满足常用尺寸下的可读性。

## 3. 范围

- 公开体验页顶部与页脚。
- 登录/注册页及 Supabase 未配置提示页。
- 忘记密码申请页内状态与登录后的重设密码页。
- 云端课程页与错题本顶部。
- 浏览器页签图标。
- 桌面、平板和手机断点下的品牌锁定组合。

## 4. 组件契约

共享 Logo 支持：

- `small`、`medium`、`large` 三种尺寸。
- 可选副标题。
- 小屏隐藏字标，仅保留图形标记的紧凑模式。
- 由外层 `Link` 或 `button` 决定导航行为，Logo 本身不绑定业务动作。

## 5. 验收标准

| AC | 验收标准 | 验证方式 |
|---|---|---|
| AC-01 | 所有现有页面使用同一共享 Logo 组件或同源图标资产 | 代码搜索、页面巡检 |
| AC-02 | 登录页不再出现与 Logo 重叠的大面积装饰圆，标题、说明和入口层级清晰 | 桌面浏览器截图 |
| AC-03 | 登录/注册表单行为、跳转目标与提示文案不变 | 交互回归 |
| AC-04 | 360px 手机宽度下 Logo、导航和表单无横向溢出 | 响应式浏览器验证 |
| AC-05 | 类型检查、ESLint 和生产构建通过 | 自动检查 |
| AC-05a | 用户可以从登录页申请密码重设邮件，回调只接受站内安全路径，并在有效会话下设置至少 8 位新密码 | 接口测试、登录浏览器回归 |

## 6. 课程插图规范

- 课程卡片不得把系统 emoji 作为正式视觉素材；已有 emoji 仅可作为尚未完成插图制作时的兼容兜底。
- 插图统一采用温暖纸张底色、水彩与轻铅笔质感，主体居中、轮廓清晰，不包含文字、水印或系统图标。
- 每节课程覆盖 5 个图像单词和第 1 个重点短语，共 6 张正式插图；生成阶段可以使用 3×2 规则网格保证同课风格一致，交付阶段切为独立 WebP，避免 CSS 精灵图映射持续膨胀。
- 正式课程插图统一存放在 Supabase Storage 的公开 `course-illustrations` Bucket，单文件不超过 5 MB，仅允许 `image/webp`。
- 对象路径使用不可变版本前缀和课程稳定标识：`v1/survival-XX-NN-name.webp`。数据库只保存对象路径，不保存完整域名，便于本地、预览和生产环境共用；单层版本目录也便于后台一次批量上传和核对。
- 前端从 `NEXT_PUBLIC_SUPABASE_URL` 构造公开资源地址；旧体验页的本地图片继续保留，课程图片加载失败时显示文字占位，不回退到系统 emoji。
- 课程初始化通过稳定 `slug`、学习项位置和 `image_key` 幂等更新，不删除或改写用户学习进度。

| AC | 验收标准 | 验证方式 |
|---|---|---|
| AC-06 | 30 节课的 150 个图像单词和 30 个重点短语均使用正式插图，不再显示 emoji | 数据校验、登录课程页面巡检 |
| AC-07 | 180 张课程插图均为独立 WebP、对象路径唯一且不超过 5 MB | 资源清单校验、Storage 检查 |
| AC-08 | 插图在桌面与手机卡片中保持比例，不拉伸；加载失败时不阻断学习 | 响应式浏览器验证、错误回退审查 |
| AC-09 | 重复执行课程数据初始化只更新课程内容与图片路径，不影响用户进度 | 生成结果幂等校验、迁移审查 |
